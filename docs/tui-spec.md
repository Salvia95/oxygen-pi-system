# 설치 TUI · Tweak TUI 화면 명세

- 대상: `installer/install.mjs` (설치 TUI), `installer/tweak.mjs` (Tweak TUI), 공용 `installer/tui.mjs`
- 상태: **승인됨 (D1–D8 모두 추천값). 구현 반영.** 구현하면서 명세와 달라진 곳은 §12 에 적었다.
- 목업의 "표시 폭" 수치는 손으로 세지 않았다. `installer/tui.mjs` 의 `displayWidth` 로 목업 블록마다 계산해 적었다 (가장 긴 줄의 칸 수 · 줄 수).
- 목업의 경로·개수·버전은 예시다 (사용자 `kim`, 파일 12,480개 등).
- "지금" 이라고 쓴 것은 이 문서를 쓴 시점의 코드(파일:줄)를 근거로 한다.

### 2.2 80×24 에서 남는 줄 계산과 배너 규칙

지금 코드에서 측정한 값 (`banner()`·`stepArt()` 를 폭을 바꿔 가며 실행하고 `displayWidth` 로 잰 값):

| 창 폭 | 배너 줄 수 | 단계 상자 줄 수 | 합계 | 24줄 창에서 본문에 남는 줄 |
|---|---|---|---|---|
| 60 | 26 | 6 | 32 | 없음 (−8) |
| 80 | 23 | 6 | 29 | 없음 (−5) |
| 100 | 14 | 3 | 17 | 7 |
| 120 | 14 | 3 | 17 | 7 |

80×24 에서는 헤더도 보이기 전에 화면이 넘친다. 지금 설치 위치 화면은 36줄을 그리고, 사용자는 아래 24줄만 본다 (§7.1 "지금"). 그래서 아래 규칙을 둔다.

- **큰 배너**는 각 TUI 를 시작할 때 한 번만 그린다 (설치 시작 / 설치 관리 시작 / Tweak 시작). 조건은 창 폭 ≥ 98(큰 글씨 한 줄, 14줄)이고 창 높이 ≥ 14 + 다음 화면 본문 줄 수 일 때다. 큰 배너 아래에서는 `환경 점검 중…` 같은 `task` 를 바로 시작해서 100ms 규칙을 지킨다.
- 큰 글씨 두 줄짜리 배너(23줄, 폭 < 98)는 쓰지 않는다.
- 나머지 화면은 모두 **3줄 프레임**(§2.1 영역 0)을 쓴다.
- 단계 상자 그림(`stepArt`)은 창 높이 ≥ 30 이고 상자가 한 줄에 들어갈 때(폭 ≥ 100)만 프레임 2행 자리에 그린다 (3줄, 프레임이 5줄이 된다). 아니면 한 줄 단계 줄(§2.3)을 쓴다.

3줄 프레임일 때 80×24 의 본문 예산:

```
24 − 프레임 3 − 여백 1 − 헤더 1 − 맥락 3 − 여백 1 − [목록] − 여백 1 − 상세 2 − 메시지 1 − 푸터 1 − 커서 줄 1
   = 목록 9줄   (맥락을 1줄로 접으면 11줄)
```

맥락 접기:

1. 목록이 목록 예산을 넘으면 맥락을 1줄로 접는다. 접힌 맥락 끝에는 `(? 설명)` 을 붙이고, `?` 키로 전체를 상세 영역 자리에 펼친다.
2. 그래도 넘치면 목록에 스크롤 창을 쓴다 (§2.4).
3. **결과형 맥락**(환경 점검 결과, vLLM 시험 결과, 설치 확인 요약, 제거 대상)은 접지 않는다. 결과형 맥락은 최대 12줄까지 쓰고, 그 대신 목록은 3개 이하, 상세는 0~1줄로 한다. 맥락 + 목록 합계가 본문 예산(80×24 에서 15줄)을 넘으면 맥락의 값 열을 줄바꿈하지 않고 말줄임한다. 단, 위험 확인 화면은 말줄임하지 않는다 (§2.5).

### 2.4 목록 행

```
  ❯ 12  레이블 (추천)            값 열 (회색)
  ↑ ↑   ↑                        ↑
  │ │   레이블 열 (최대 24칸)     value rail = 레이블 열 최대 폭 + 2
  │ 번호 (오른쪽 정렬)
  포커스 표식 (칸 3)
```

다중 선택 행에는 번호 뒤에 상태 상자 `[✔]`·`[ ]`·`[■]`·`[·]` 와 공백 1칸이 들어간다.

| 규칙 | 내용 |
|---|---|
| 번호 | TTY·줄 입력 모드 모두 보인다 (D4). 제목 행에는 번호가 없다. 비활성 항목에도 번호를 준다. 그래야 조건에 따라 번호가 밀리지 않는다 (§7 C-W2, C-I12) |
| 항목명 — 설명 | 모든 select·multiselect 행은 **항목명(짧은 명사구) → 설명** 순서다. 설명은 설치 TUI 에서는 그 항목을 고르면 하는 일, Tweak 에서는 현재 값(값이 없으면 하는 일)이다. 기술 이름(vLLM·SQLcl·psmux·MCP·dbhub·usql·extension·skill id)은 항목명에 쓰지 않고 설명 맨 앞에 둔다. 넓은 폭 TTY 에서는 value rail 이 구분 역할을 하므로 `—` 를 찍지 않는다. 줄 입력 모드에서는 `—` 를 찍는다 (D6). 이름 기준과 좁은 폭 규칙은 §11 |
| 상태 문구의 위치 | 레이블 바로 뒤(`(추천)`, `(현재)`) 또는 값 열 맨 앞(`필수`, `반입 안 됨`, `사용 불가`)에 둔다. 상태 문구는 말줄임 대상이 아니다. 말줄임은 그 뒤의 설명만 한다 |
| 값 열 | 현재 값(Tweak), 경로·버전(설치), 한 줄 설명. 회색 |
| 좁은 폭 (< 80) | §11.4 의 세 단계 규칙을 따른다: ① 한 줄에 들어가면 그대로 → ② 아니면 설명을 둘째 줄로 → ③ 둘째 줄을 쓰면 목록이 넘칠 때는 설명을 숨기고 상세 첫 줄로 옮긴다 (상세 최대 3줄). 상태 문구(`필수`, `반입 안 됨` 등)는 ③ 에서도 항목명 옆에 남긴다 |
| 넘칠 때 | 스크롤 창. 위/아래로 숨은 줄이 있으면 목록 첫 줄·마지막 줄 자리에 `↑ 위에 n줄 더` / `↓ 아래에 n줄 더` (회색, 번호 칸에 맞춤). 포커스한 행과 그 행의 그룹 제목은 항상 보이게 한다. 페이지 넘김(PgUp/PgDn)은 두지 않는다. 목록이 가장 긴 곳이 19줄이라 스크롤로 충분하다 |
| 순환 | 맨 아래에서 ↓ 를 누르면 맨 위로 간다 (지금과 같음) |
| 초기 포커스 | 권장 항목. 권장이 없으면 현재 값. 그것도 없으면 첫 번째 선택 가능 항목이다. 위험 확인에서는 "안 함" 쪽 (§4.6) |

### 2.5 고유명사 설명 · 정렬 · 말줄임

- **용어 설명.** 용어집(§5.2)에 있는 단어가 헤더·맥락·포커스한 행에 나오면 푸터에 `? 용어` 가 생긴다. `?` 를 누르면 상세 영역 자리에 `vLLM  사내 GPU 서버에서 모델을 띄우는 서버 프로그램…` 형식으로 최대 4줄을 펼친다. 아무 키나 누르면 닫힌다. 줄 입력 모드에서는 프롬프트에 `?` 를 입력하면 같은 설명을 출력하고 다시 묻는다. 본문 안에 따로 표식(밑줄·윗첨자)은 넣지 않는다. 터미널마다 다르게 그려지고, 한 줄에 용어가 여럿이면 지저분해지기 때문이다.
- **폭.** 모든 정렬·말줄임은 `displayWidth` 기준이다. `padEnd`·`length` 로 맞추지 않는다 (지금 `install.mjs:447` 의 `padEnd(12)` 가 한글 레이블을 어긋나게 만든다. §7.6).
- **말줄임 기호**는 `…` (U+2026, 1칸)다. 2칸 글자(한글·전각)의 중간은 자르지 않는다.
- 자르는 위치:

| 대상 | 규칙 | 예 (폭 32) |
|---|---|---|
| 설명문 | 끝을 자른다. 끝에서 8칸 안에 공백이 있으면 공백에서 자르고, 없으면 글자 경계에서 자른다 | `터미널 멀티플렉서 (tmux 호환) ·…` |

### 2.7 줄 입력 모드 화면 (TTY 아님)

TTY 모드와 영역 순서는 같다. 화면을 지우지 않고 아래로 이어 쓰므로 프레임을 한 줄로 줄인다.

```
── <프레임 2행 내용> ─────────     (예: ── 설치 2/8 위치 ─────)
헤더
맥락 (줄바꿈 78칸)
  번호) 목록 행               (값 열 포함, 말줄임 안 함 — 로그 검색용)
범례 (multiselect 에 잠금·비활성이 있을 때만)
프롬프트 한 줄
```

- 큰 배너는 프로그램 시작 때 한 번만 출력한다. 지금은 `ui.screen()` 을 부를 때마다 배너 14~23줄을 다시 출력한다 (`tui.mjs:171`). 그래서 회귀 테스트 로그가 길어진다.
- 상세 영역은 출력하지 않는다. `?` 를 입력하면 모든 선택지의 상세와 용어 설명을 출력한다. 단, 위험 확인 화면은 상세를 항상 출력한다.
- 프롬프트 형식 (§4.9 와 같은 단어):

| 유형 | 프롬프트 |
|---|---|
| select | `번호 [1] · < 이전 · ? 설명: ` (이전이 없으면 `< 이전` 을 뺀다) |
| multiselect | `번호 (예: 2,4 · +6 -3 · 빈칸=표시된 대로 · -=필수만 · < 이전): ` (`-=필수만` 은 잠금 항목이 있을 때만) |
| input | `> [기본값] · < 이전: ` (mask 이고 기본값이 있으면 `[저장됨]`) |
| confirmTyped | `> 확인하려면 oxygen-pi 입력 · < 취소: ` |
| pause | `Enter 계속: ` / `Enter 종료: ` |

- multiselect 의 `+N`·`-N` 은 **새 문법**이다. "표시된 상태에서 N 을 켜기 / 끄기"를 뜻하고, 쉼표·공백으로 여러 개를 쓸 수 있다. 숫자만 쓴 입력(`2,4`)은 지금처럼 "정확히 이것만"이다. 둘을 섞으면 검증 오류로 처리한다. skill 13개 가운데 하나만 끄려고 나머지 12개를 입력하지 않게 하기 위해서다. 지금 회귀 테스트가 쓰는 `""` 와 `"1,2"` 는 뜻이 그대로다.
- 입력이 끝나면(EOF) 스택 대신 `입력이 끝나 중단했습니다 (줄 입력 모드). 기다리던 질문: <헤더>` 한 줄을 출력하고 종료 코드 1 로 끝낸다. 지금은 `오류: Error: 입력이 끝났습니다 (stdin EOF)` 와 스택이 나온다 (`tui.mjs:205`, `install.mjs:709`). 회귀 테스트 입력 순서가 어긋났을 때 어느 질문에서 멈췄는지 바로 보이게 하기 위해서다.

모든 상태는 **기호(또는 문구) + 색**으로 이중 표현한다. 무색에서는 기호와 문구만 남는다.

| 상태 | 기호 | 색 | 문구 변화 | 무색에서 구분되는 근거 | 출발점 (지금) |
|---|---|---|---|---|---|
| 기본 | 없음 (포커스 칸은 공백) | 기본색 | — | — | 같음 |
| 포커스 | `❯` (칸 3) | 행 전체 청록 | 상세 영역에 그 행 설명 | `❯` | 같음 (`tui.mjs:228`) |
| 선택됨 (multiselect) | `[✔]` | 초록 | — | `✔` | TTY 는 같음. 줄 입력 모드 `[x]` 는 `[✔]` 로 맞춘다 |
| 선택 안 됨 | `[ ]` | 기본색 | — | 빈 상자 | 같음 |
| 잠금 (필수) | `[■]` | 회색 | 값 열 맨 앞에 `필수`. Space 를 누르면 메시지 `node 는 필수 구성요소라 해제할 수 없습니다` | `■` + `필수` | TTY 는 같음. 줄 입력 모드 `[#]` 는 `[■]` 로 맞춘다 |
| 비활성 (고를 수 없음) | `[·]` (multiselect) / 번호 뒤 공백 그대로 (select) | 레이블·값 회색 | 값 열 맨 앞에 짧은 이유. 예: `반입 안 됨`, `설치 안 됨`, `사용 불가`. 상세에 `사용 불가  <이유>` / `해결  <방법>` | `·` + 이유 문구 | 새로 만든다. 근거: 지금은 조건이 안 맞는 항목을 목록에서 빼 버려서 번호가 밀리고 이유도 보이지 않는다 (`tweak.mjs:391`, `install.mjs:655`, `components.mjs:232-241`) |

| 결과: 성공 | `✔` | 초록 | — | `✔` | 같음 |
| 결과: 경고 | `!` | 노랑 | — | `!` | 같음 |

| 켜짐 / 꺼짐 (요약 표시) | `●` / `○` | 초록 / 회색 | — | 기호 모양 | 같음 (`tweak.mjs:235, 354`) |

바꾼 기호와 근거:

- 줄 입력 모드 `[x]`·`[#]` → `[✔]`·`[■]`. 같은 상태에 두 기호를 쓰지 않는다. 줄 입력 모드도 UTF-8 터미널(mintty)과 로그 파일에서만 쓰이므로 ASCII 로 대체할 이유가 없다.
- 비활성 `[·]`. 빈 상자 `[ ]` 와 모양이 다르고, `✔`·`■` 와도 겹치지 않는다.
- 나머지(`❯`, `[✔]`, `[■]`, `✔`/`✖`/`!`, `●`/`○`, `▶`)는 그대로 둔다.

|---|---|---|
| 청록 | 36 | 포커스, 현재 단계, 그룹 제목, 제품 이름, 스피너 |
| 초록 | 32 | `✔`, `[✔]`, `(추천)`, 지난 단계 |
| 노랑 | 33 | `!` 경고, 위험 레이블, 해제 불가 메시지 |
| 빨강 | 31 | `✖` 오류 줄만 |
| 회색 | 90 | 값 열, 키 안내, 속성 이름, 비활성, 남은 단계, `(현재)` |
| 굵게 | 1 | 헤더, 그룹 제목, 현재 단계 |

색을 끄는 조건 (하나라도 해당하면 끈다): `NO_COLOR` 가 비어 있지 않음, `TERM=dumb`, 출력이 TTY 아님. 이 판단은 `UI` 인스턴스의 `output` 기준으로 한다. 지금은 모듈을 불러올 때 `process.stdout` 기준으로 한 번 정하므로 (`tui.mjs:5`), 가짜 터미널 테스트에서 무색을 검사할 수 없다. `TERM=dumb` 이면 커서 이동도 못 쓰므로 줄 입력 모드로 동작한다.

### 4.2 헤더

- 의문문 한 문장. 표시 폭 60칸 이내. **결정할 대상을 문장 앞쪽에 둔다.**
- 텍스트 입력의 헤더도 의문문으로 쓴다 (`어느 LLM 서버에 연결할까요?`). 무거운 확인 입력도 헤더는 의문문(`설치 폴더를 정말 삭제할까요?`)이고, 입력할 단어는 맥락에 쓴다 (§4.6).
- 사용자의 의향이 아니라 사실을 묻는 질문(파일이 어디 있는지 등)은 `-ㄹ까요?` 로 쓸 수 없으므로 `-습니까?` 를 허용한다: `Oracle SQLcl 압축 파일은 어디에 있습니까?`
- 결과를 알리는 문장(`설치를 마쳤습니다.`)은 헤더에 붙이지 않고 맥락 첫 문장으로 쓴다. 헤더는 한 문장이다.
- 결정을 묻지 않는 화면(진행 중, 완료, 치명 오류)의 헤더는 평서문이다. 진행 중은 `설치하는 중입니다`, 완료는 `✔ 설치를 마쳤습니다`, 치명 오류는 `설치를 계속할 수 없습니다` 처럼 쓴다. 이 화면들은 목록이 없거나 `Enter 계속/종료` 뿐이다.

| 좋은 예 | 나쁜 예 | 이유 |
|---|---|---|
| `어디에 설치할까요?` | `설치 위치` | 질문이 아님 |
| `agent-browser 가 쓸 브라우저는 무엇으로 할까요?` | `agent-browser 가 사용할 브라우저` | 질문이 아님 |
| `코딩용 기본 모델은 무엇으로 할까요?` | `코딩용 모델 (기본 모델)` | 질문이 아님 |
| `이대로 설치할까요?` | `설치 내용 확인` | 결정할 것이 드러나지 않음 |
| `무엇을 바꿀까요?` | `바꿀 항목을 고르세요` | 명령형 |
| `동작 시험(verify)을 실행할까요?` | `동작 시험을 실행하시겠습니까?` | 공손 반복 |
| `긴 경로(124자)에 그대로 설치할까요?` | `경로가 깁니다 (124자). 일부 Windows 도구는 긴 경로에서 문제가 생길 수 있습니다. 계속할까요?` | 60칸 초과, 근거가 헤더에 들어감 → 맥락으로 옮긴다 |

### 4.3 선택지 레이블

- 고른 뒤 일어나는 행동을 쓴다. `예`·`아니요`·`확인`·`계속` 만 단독으로 쓰지 않는다.
- 같은 목록 안에서는 문형을 통일한다 (모두 `~에 설치` / `~ 사용` 처럼 명사구).
- 다음 화면에서 값을 입력하는 선택지는 끝에 `…` 를 붙인다: `다른 폴더 직접 입력…`.
- 목록에서 빠져나가는 선택지는 끝에 둔다. 순서는 `← 이전`, 그다음 `… 취소`/`종료` 다. `취소` 는 흐름 전체를 그만두는 뜻으로만 쓴다 (§5.1).

| 좋은 예 | 나쁜 예 |
|---|---|
| `동작 시험 실행` / `건너뛰기` | `예` / `아니요` |
| `설치 계속` / `설치 취소` | `계속` / `취소` |
| `기본 위치에 설치` / `지금 폴더 그대로 사용` / `다른 폴더 직접 입력…` | `기본 위치에 설치` / `지금 폴더에서 그대로 사용 (복사 안 함)` / `직접 입력` |
| `tdb 연결 삭제` / `삭제 취소` | `예` / `아니요` |
| `제한에 맞춘 설정 적용 (추천)` / `설정 그대로 두기` | `제한에 맞춘 설정 적용 (권장)` / `설정 바꾸지 않음` |

`confirm` 은 레이블 두 개를 반드시 받는다: `confirm(question, { yes: "동작 시험 실행", no: "건너뛰기", initial, level })`. 순서는 항상 **1 = 진행, 2 = 안 함**이다. 이렇게 하면 지금 회귀 테스트가 넣는 번호가 바뀌지 않는다.

### 4.4 상세 영역

- 두 줄이다: `바뀌는 것  …` / `되돌리기  …`. 비활성 항목은 `사용 불가  …` / `해결  …` 으로 쓴다.
- 권장 항목은 근거를 `바뀌는 것` 앞에 한 줄 더 쓸 수 있다. 이때 상세는 최대 3줄이고, 그 화면의 맥락은 1줄로 접는다.
- 파일을 바꾸는 행동은 파일 이름을 쓴다 (`agent/oxy.env`, `agent/skills/<이름>`).

| 좋은 예 | 나쁜 예 |
|---|---|
| `바뀌는 것  agent/oxy.env 의 GITLAB_HOST` / `되돌리기  같은 항목에서 다시 바꿀 수 있습니다` | `GitLab 호스트를 설정합니다` |
| `사용 불가  반입되지 않았습니다` / `해결  인터넷 PC 에서 fetch 로 받아 다시 번들링하세요` | `(없음)` |

### 4.5 권장 표시

- 레이블에는 `(추천)` 만 붙인다. 근거는 상세 영역에 쓴다 (`agent-browser 의 기본 브라우저로 가장 많이 검증됨`).
- `(권장)` 은 쓰지 않는다 (`install.mjs:351`, `tweak.mjs:111` 을 바꾼다).
- 모델 계열을 id 로 추정한 것도 `(추천)` 으로 표시한다. 상세에는 `모델 이름 qwen3.6-coder-30b 으로 추정했습니다` 라고 쓴다 (지금 값 열의 `id 로 추정`, `install.mjs:409`).

### 4.6 위험 행동 (clig.dev 확인 단계, D5)

| 단계 | 행동 (이 TUI 에서) | 확인 방식 | 초기 포커스 |
|---|---|---|---|
| 가벼움 | oxy.env 값 바꾸기 (vLLM·모델·GitLab·한도·엔드포인트), extension·skill 켜기/끄기, 브라우저 바꾸기, DB 연결 추가·편집 | 확인하지 않는다. 저장하고 결과를 한 줄로 보여 준다 (§4.8) | — |

- 설치·설정 변경의 단계 흐름에서는 확인 단계 화면(§7.6)이 중간 확인을 대신한다. 해제할 등록이 있으면 요약에 `(해제: 바로가기)` 로 보인다. 그래서 단계 흐름에는 따로 확인을 추가하지 않는다.
- 위험 레이블에는 대상과 수량을 쓴다.

| 좋은 예 | 나쁜 예 |
|---|---|
| `! 설치 폴더 삭제하고 등록 해제` + 맥락 `삭제  C:\Users\kim\AppData\Local\Programs\oxygen-pi (파일 12,480개 · 1.1GB)` · `함께 삭제  DB 연결 2개와 저장된 비밀번호 (백업하지 않음)` · `백업  agent/oxy.env → …\oxy.env.bak` | `제거 (설정 파일은 백업)` |
| `tdb 연결 삭제` + 맥락 `connections.json 의 tdb · 저장된 비밀번호 · usql/dbhub 등록이 사라집니다` | `tdb 연결을 삭제할까요? (저장된 비밀번호도 삭제)` + `예/아니요` |

### 4.7 텍스트 입력

- 헤더는 의문문이다. 형식 예시는 맥락 영역에 `예: …` 로 쓴다.
- 검증 실패 문구는 `✖ <무엇이 틀렸나>. <어떻게 고치나>` 형식이다.

| 좋은 예 | 나쁜 예 |
|---|---|
| `✖ http:// 또는 https:// 로 시작해야 합니다. 예: http://vllm.example.internal:8000` | `✖ 올바른 URL 이 아닙니다` |
| `✖ 절대 경로가 아닙니다. C:\ 처럼 드라이브부터 입력하세요` | `✖ 절대 경로(C:\...)를 입력하세요` |
| `✖ 8192 이상의 숫자여야 합니다. vLLM --max-model-len 값과 맞추세요` | `✖ 8192 이상의 숫자를 입력하세요` (고치는 근거 없음) |
| `✖ 이미 있는 연결 이름입니다. 다른 이름을 쓰거나 목록에서 tdb 를 편집하세요` | `✖ 이미 있는 이름입니다` |
| `✖ 값이 필요합니다` (필수 입력 공통) | `필수 입력` |

- **비밀값** (`mask`)
  - TTY 에서는 `•` 로 가린다.
  - 줄 입력 모드에서는 프로그램이 입력을 다시 출력하지 않는다. 지금은 `#line()` 이 받은 값을 그대로 출력해서 (`tui.mjs:206`) API 키와 DB 비밀번호가 로그(`out.txt`)에 남는다. 값 대신 `(입력됨)` 을 출력한다.
  - F4 가 사실이면, 줄 입력 모드의 mask 입력 위에 `줄 입력 모드에서는 입력한 글자가 보일 수 있습니다. Windows Terminal 에서 실행하면 가려집니다` 를 회색으로 한 줄 띄운다.
  - 비밀값은 명령줄 인자·환경변수로 받지 않는다 (지금도 받지 않는다. 유지).
  - 확인 화면에는 `입력됨` / `없음` 만 쓴다.

### 4.8 성공 출력

- 상태가 바뀐 것을 한 줄로 확인해 주고, 필요하면 다음에 할 일(명령)을 쓴다.
- Tweak 의 가벼운 변경은 결과 화면에서 Enter 를 기다리지 않는다. 허브(또는 하위 메뉴) 화면의 메시지 줄에 결과를 보여 준다. `✔ GitLab 호스트 저장 · 실행 중인 pi 는 다시 시작하면 적용됩니다`
- 결과를 읽어야 다음에 쓸 수 있는 경우만 `pause` 를 쓴다: DB 연결 저장(사용법·도구 이름), 설치·업데이트·제거 완료, 오류.
- 설치 완료 화면은 `시작하기` 명령 목록으로 끝난다. 명령은 자르지 않는다.

### 4.9 키 안내 (푸터)

형식: `키 동작` 을 ` · ` 로 잇는다. 순서는 고정이다:
`↑↓ 이동` → `번호` → `Space 선택/해제` → `Enter 확정` → `Esc 이전` → `? 용어` → `Ctrl+C 종료`.

| 유형 | 푸터 |
|---|---|
| select | `↑↓ 이동 · 번호 · Enter 확정 · Esc 이전 · Ctrl+C 종료` |
| multiselect | `↑↓ 이동 · 번호 · Space 선택/해제 · Enter 확정 · Esc 이전 · Ctrl+C 종료` |
| input | `Enter 확정 · Ctrl+U 지우기 · Ctrl+V·우클릭 붙여넣기 · Esc 이전` |
| confirmTyped | `Enter 삭제 · Ctrl+U 지우기 · Esc 취소` |
| 허브 (Tweak 메인, 설치 관리) | `↑↓ 이동 · 번호 · Enter 확정 · Esc 종료` |
| pause | `Enter 계속` / `Enter 종료` |
| 진행 중 (설치·업데이트 실행) | `Ctrl+C 중단 (다시 실행하면 이어서 설치)` |

- `Enter 선택`(select)·`Enter 확정`(multiselect)·`Enter 확인`(input) → **`Enter 확정`** 하나로 통일한다. 같은 키가 같은 일("이 화면의 값으로 끝내기")을 하기 때문이다.
- 폭이 모자라면 우선순위가 낮은 것부터 뺀다: `번호` → `? 용어` → `Ctrl+C 종료` → `Esc 이전`. `Enter`·`↑↓`·`Space` 는 빼지 않는다.
- `Esc 이전` 은 이전이 있는 화면에서만 보인다. 허브에서는 Esc 가 종료다 (저장은 항목마다 이미 끝났으므로 확인하지 않는다).
- `pause` 의 `Enter 를 누르면 계속합니다` / `Enter 를 누르면 종료합니다` / `모델 이름을 직접 입력합니다. Enter` (`tweak.mjs:286`) → 푸터 형식 `Enter 계속` 으로 통일한다. 안내 문장은 맥락 영역에 쓴다.

### 4.10 오류 · 연결 실패 · 진행 · 빈 목록

**오류 블록** (가장 중요한 정보 = 해결 방법을 마지막 줄에. 빨강은 첫 줄 `✖` 만):

```
  ✖ <무엇이 실패했나 — task 레이블>
    원인  <사람 말로 바꾼 원인>  (원문 코드는 회색 괄호)
    해결  <할 일>. <다시 실행할 명령>
```

| 상황 | 원인 문구 | 해결 문구 |
|---|---|---|
| vLLM `ECONNREFUSED` | 서버가 연결을 거부했습니다 (ECONNREFUSED) | 포트가 맞는지, vLLM 이 실행 중인지 확인하세요 |
| vLLM `ENOTFOUND` | 호스트 이름을 찾지 못했습니다 (ENOTFOUND) | 주소 철자와 사내 DNS 를 확인하세요 |
| vLLM 시간 초과 (`TimeoutError`, 6초) | 6초 안에 응답이 없습니다 | 방화벽·프록시 설정을 확인하세요 |

**바뀐 뒤**: "선택" 단계를 아래 순서로 바꾼다.
1. 구성요소 다중 선택 (§6.2 목업)
2. agent-browser 를 골랐을 때만: 브라우저 단일 선택 (§7.4)

다중 선택의 규칙:

| 규칙 | 내용 |
|---|---|
| 목록 | `CATALOG` 의 `kind !== "engine"` 인 선택 구성요소. `GROUPS` 순서로 제목 행을 둔다. 필수(core)는 잠금 행 하나 `core 5개` 로 묶는다. 브라우저(chromium, chrome)는 2단계 화면에서 고른다 (같은 결정을 두 번 묻지 않는다) |
| 초기 선택 | 신규 설치: 번들에 있는 것 모두 (사용자가 fetch 로 직접 고른 것들이다). SQLcl·graphin 처럼 번들에 없지만 zip 으로 설치할 수 있는 것은 해제 상태 |
| 비활성 | 번들에 없고 zip 설치도 안 되는 것: `반입 안 됨` (graphin 은 `vendor/graphin/ 에 직접 반입`, 나머지는 `fetch 후 다시 번들링`) |
| 경고 | SQLcl 행: 점검 단계에서 Java 17 을 못 찾았으면 값 열에 `! Java 17 없음 — 실행 불가`. 고를 수는 있다 |
| 의존 | agent-browser 를 해제하면 2단계를 건너뛰고 `OXY_BROWSER=none` 으로 둔다. usql·dbhub 를 둘 다 해제하면 확인 요약에 `DB 연결: 사용 불가 (usql·dbhub 없음)` 를 보인다 |
| 결과 | 해제한 구성요소의 파일은 복사하지 않는다 (`copyExcludes` 를 `CATALOG` 에서 만든다. 구성요소마다 복사 경로 목록이 필요하다: 예 `psmux → bin/psmux.exe`, `dbhub → vendor/dbhub`, `sqlcl → runtime/sqlcl`) |
| 설정 변경 (`reconfigure`) | 이 화면을 쓰지 않는다. 설정 변경은 파일을 복사하지 않기 때문이다. 지금처럼 SQLcl → 브라우저 화면을 쓰고 문구만 고친다 |
| 업데이트 | 번들에 있지만 아직 설치되지 않은 선택 구성요소가 있을 때만 이 화면을 보인다. 이때 설치된 것은 잠금(`설치됨`), 새것은 해제 상태로 둔다. 설치된 구성요소를 빼는 것(삭제)은 이 명세 범위 밖이다 (§10 A2) |

**줄 입력 순서 바뀜 (회귀 테스트 수정 필요)**: 신규 설치의 세 번째 답(`$long` 다음)은 지금 SQLcl 화면의 `1`(번들에 포함된 SQLcl 설치)이다. 이 자리가 구성요소 다중 선택이 된다. 여기에 `1` 을 넣으면 "1 번만 선택"이 되어 나머지가 **모두 해제된다**. 반드시 `""`(표시된 대로)로 바꿔야 한다. 그 뒤 브라우저 `2`(Chromium)는 그대로다. 번들에 SQLcl 이 있으면 SQLcl 을 따로 묻지 않는다.

## 10. 대안 (규칙은 바꾸지 않고 제안만)

## 11. 추가 검토 (메뉴 명칭·구성·항목 표시)

사용자 검토 요청 세 가지(① 메뉴·단계 이름은 구현 용어가 아닌 일반어로, 하는 일 기준으로 묶기 ② 모든 선택 항목을 "항목명 — 설명" 순서로 ③ 그에 따른 회귀 테스트 영향)를 반영한 결과다. 새로 정할 것은 결정 필요 D6~D8 에 추천값과 함께 올렸다.

### 11.1 이름 기준

| 기준 | 내용 |
|---|---|
| 항목명 | 사용자가 하려는 일이나 대상을 짧은 일반어 명사구로 쓴다. 표시 폭 20칸 이내 (`(추천)` 같은 상태 표시를 붙여도 24칸 이내) |

### 11.4 "항목명 — 설명" 표시 규칙과 좁은 폭

| 폭 | 규칙 | 목업 |
|---|---|---|
| ≥ 80 (TTY) | 한 줄. `항목명` 을 레이블 열 폭으로 채우고 2칸 뒤 설명 (value rail). `—` 는 찍지 않는다 (D6). 설명이 넘치면 §2.5 규칙으로 끝을 말줄임한다. 식별자는 자르지 않고, 들어가지 않으면 설명에서 빼고 상세로 보낸다 | §7.9, §6.2 |
| 60–79 (TTY) | ① `항목명 + 2칸 + 설명` 이 한 줄에 들어가면 한 줄로 쓴다. ② 아니면 설명을 **둘째 줄**로 보낸다. 둘째 줄은 항목명 열(번호 뒤)에서 시작하고 회색이며 폭에 맞춰 끝을 말줄임한다. ③ 둘째 줄을 쓰면 목록 예산(§2.2)을 넘을 때는 설명을 모두 숨기고, 포커스한 항목의 설명을 상세 첫 줄(`현재` 또는 `설명`)로 옮긴다. 상태 문구(`필수`, `반입 안 됨`, `사용 불가`)는 ③ 에서도 항목명 오른쪽에 남긴다 | 아래 LLM 연결 60칸(②), §7.9 60칸(③), §6.2 60칸(③) |
| < 60 | ③ 과 같다. 항목명도 넘치면 끝을 말줄임한다 (보장 안 함) | — |
| 줄 입력 모드 | 한 줄 `번호) 항목명 — 설명`. 항목명은 레이블 열 폭으로 맞추고, 설명은 자르지 않는다 (로그 검색용) | §6.2, §7.9, §7.12 줄 입력 목업 |
| 맥락의 속성 줄 (요약·점검 결과) | 이 규칙의 대상이 아니다. 선택 항목이 아니라 `속성 이름  값` 이다 (§2.1 기준선) | §7.2, §7.6 |

②·③ 중 무엇을 쓸지는 화면마다 정하지 않고 `UI` 가 계산한다 (tui.mjs 공용 규칙). 한 화면 안에서 섞지 않는다. ② 를 쓸 때는 모든 행을 두 줄로 쓴다. 그래야 번호 칸과 항목명 열이 들쭉날쭉하지 않다.

### 12.3 확인하지 못한 것

- F1 (`/reload` 로 skill 반영 여부), F2 (conhost Ambiguous 폭), F3 (IME), F4 (mintty 에코)는 실제 터미널에서 확인하지 않았다. F4 는 사실로 가정하고 줄 입력 모드 mask 입력 위에 경고를 띄운다. 저장 문구는 F1 확인 전이라 "다시 시작하면 적용" 이다.
- K10·K12·K14·K26·K27 은 자동 검사를 만들지 않았다 (화면별 헤더·항목명 목록을 모으는 장치가 없다). K20–K24 는 눈으로 확인할 항목이다.
- §10 A5 (동기 `spawnSync`·`walk` 를 비동기로)는 하지 않았다. 대신 점검·브라우저 찾기·파일 세기·복사 앞에 `task` 를 먼저 그린다.
