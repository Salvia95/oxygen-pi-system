# Completed Flow · Task 단위 롤백 명세

Flow Monitor 의 Before Commit Task 를 없애고, 끝난 Flow 를 보여 주는 **Completed Flow** 영역과 **Task 단위 롤백**을 둔다.
목적: 작업 흐름을 기록해 세션의 작업을 진행 중에 보고, 나중에 찾아보고, 필요하면 그 지점까지 되돌린다.
진행 상태: [진행판](dev-board.md) 의 `flow-rollback` 행. 관련: `docs/flow-spec.md` (기록) · `docs/flow-view-spec.md` (화면).

## 0. 요청과 결정

요청 (사용자, 2026-11-14)
- "Before Commit Task를 보여줄 필요가 있을까? Completed Flow를 보여주고, 모두 커밋되어 완전히 원복이 가능한 Flow는 체크 표시로, 전체 커밋이 되지 않거나, 불완전한 Flow는 느낌표로 표시해두고 Flow 내부 태스크명 + 요약만 보고 에이전트가 롤백을 시도하도록 설계하는게 더 맞아보여서 말이야"
- "우리가 Flow를 설계한 이유는 결국 작업 흐름을 기록해 세션의 전체 작업 흐름을 진행 중 시각적으로 보고, 이후 찾아보고 롤백이 필요하면 그 지점까지 찾아올라갈 수 있는건데 지금 구조는 그 목적을 온전히 못채우는 것 같아"

- D2. 롤백 단위는 **Task** 다: "Completed Flow에서 특정 Task를 선택해서 롤백하면 Flow 내에서 그 Task의 위치까지 롤백되는거야".

## 1. 확인된 사실 (2026-11-14)

- 지금 Before Commit Task 는 마지막 커밋 뒤의 결정 · 변경 파일 · 실패를 보인다. 작업 폴더가 git 이 아니면 커밋이 생기지 않아 비워지지 않는다 (설치본 cozy-example: 변경 파일 23개, 실패 5개가 11-13 19:29 부터 쌓임. `cozy-example` · `library-rental` 모두 git 저장소가 아님).
- 지금 flow 기록(`flow.json`)의 할 일에는 시작 · 끝 시각과 연결된 커밋 노드가 있다. 커밋 노드는 작업 저장소가 git 일 때만 생긴다.
- `/flow rollback nN` 은 git 저장소에서 nN 뒤의 커밋을 `git revert` 한다. git 이 아니면 쓸 수 없다.
- 로컬 git 은 2.56 이다. `git merge-tree --write-tree` 로 작업 폴더를 건드리지 않고 충돌을 미리 볼 수 있다.

## 2. 용어

| 말 | 뜻 |
| --- | --- |
| Flow | 요청 · 목표 하나의 기록 (목표 · 계획 · 커밋 노드 · 결정). 지금 진행 중인 것 하나 + 끝난 것들 |
| Task | Flow 계획의 할 일. 화면의 `[1/5] 마이그레이션` 과 그 아래 `├ [1/2] …` |
| 스냅숏 | 그림자 저장소에 남긴, 그 시점 작업 폴더 전체의 커밋 |
| 롤백 지점 | Task 하나. "그 Task 가 끝난 때의 상태로" 되돌린다 |

## 3. 화면

Overall Task 아래 영역을 바꾼다. Before Commit Task 는 없앤다 (그 결정 · 변경 파일은 각 Task 의 요약으로 들어간다).

```
── Overall Task ───────────────────
…                                    ← 지금 Flow (그대로)
── Completed Flow ─────────────────
! 도서관 대여 앱 · 반납 · 연체  11-14   ← 최근 Flow 가 위. 기호는 그 Flow 에서 가장 나쁜 Task 의 것
✓ 로그인 API 추가               11-13
```

Enter 로 펼치면 Task 와 롤백 가능 여부가 보인다.

```
! 도서관 대여 앱 · 반납 · 연체  11-14
├ ✓ [1/5] 마이그레이션
├ ✓ [2/5] loan 반납                    ← 여기를 고르고 r: [3/5] 이후의 변경을 되돌린다
├ - [3/5] 도서 대여 중 표시 (뺌)
├ X [4/5] 테스트 추가                   ← 되돌리면 뒤의 작업과 충돌이 예상됨
└ ! [5/5] verify 재실행                 ← 기록 밖 변경이 있어 에이전트가 되돌리기를 시도
```

- 기호 (Task 마다, "이 Task 의 위치까지 되돌리기"가 어떤지)
  - `✓` 완전히 되돌릴 수 있다: 이 Task 뒤의 변경이 모두 스냅숏에 있고, 되돌려도 충돌이 없다.
  - `!` 불완전: 이 Task 뒤의 변경 가운데 스냅숏에 없는 것이 있다 (뺀 큰 폴더 · 작업 폴더 밖 파일 · DB 서버 · 설치한 패키지 등). 에이전트가 Task 이름 · 요약 · 변경 파일을 보고 되돌리기를 시도한다.
  - `X` 충돌 예상: 되돌리면 뒤의 작업(뒤의 Flow · 지금 작업 중인 변경)과 부딪힌다. 롤백을 막고 이유를 보인다.
- 키: `▲▼` 이동, `Enter` 펼치기, `r 되돌리기` 이 Task 까지 (확인 팝업, 처음 포커스는 취소), `u 되돌리기 취소` 마지막 되돌리기를 취소.
- 롤백한 Flow 에는 `↶ [2/5] 까지 되돌림 11-14 10:20` 줄이 붙는다 (기록은 지우지 않는다, D3).
- 지금 Flow 의 끝난 Task 도 Overall Task 에서 같은 키(`r` · `u`)로 롤백한다 (D8). 기호(✓ ! X)는 Completed Flow 와 같은 규칙으로 끝난 Task 앞에 보인다.

### 3.1 확인 문구 (D9)

롤백과 되돌리기는 파일을 바꾸거나 지우므로 실행 전에 늘 확인한다. 모니터는 기존 작업 중지 팝업과 같은 모양, pi 에서 `/flow rollback` 을 직접 쓰면 pi 확인 창.

```
┌ 되돌리기 ─────────────────────────┐
│ "[2/5] loan 반납" 이 끝난 상태로   │
│ 되돌립니다.                         │
│ 파일 12개가 바뀌거나 삭제됩니다.    │
│ 계속할까요?                         │
│          [ 취소 ]  [ 되돌리기 ]     │
└────────────────────────────────────┘
```
- 처음 포커스는 `취소`. `!` 이면 한 줄을 더한다: `원격저장소에 없는 변경은 작업기록을 토대로 에이전트가 되돌리기를 시도합니다.` (D12, 사용자 문구 그대로)
- 되돌리기 취소(`u`)는 제목 `되돌리기 취소`, 첫 줄 `마지막 되돌리기("[2/5] loan 반납" 까지)를 취소합니다.`, 버튼 `[ 닫기 ]  [ 되돌리기 취소 ]`.
- 파일 수는 미리 본 결과(§5 의 2)에서 센다. 정확한 문구 · 폭은 화면 구현 때 80×24 캡처로 맞춘다.

## 4. 기록: 그림자 저장소

- 위치: `<프로젝트>/.oxy/flow/shadow/<작업 폴더 이름-해시>/` (git 의 GIT_DIR). 작업 폴더마다 하나 (D11). 작업 트리는 Flow 의 작업 폴더(`work.root`, 없으면 pi 를 시작한 폴더).
- 넣지 않는 것 (D7): 작업 폴더의 `.gitignore` (git 일 때) · 기본 목록 `node_modules` `target` `build` `dist` `.venv` `*.log` · 20MB 를 넘는 파일. 상한 안의 DB 파일(SQLite 등)은 넣는다. 넣지 않은 곳이 바뀌면 그 Task 는 `!`.
- 보관 (D10): Flow 기본 10개. Tweak 의 설정 항목으로 조절한다 (화면 위치 · 문구는 `docs/tui-spec.md` 에 구현 전 정한다). 넘으면 가장 오래된 Flow 의 기록 · 스냅숏부터 정리하고(`git gc`), 정리된 Flow 는 Completed Flow 에서 빠진다.
- 사용자 저장소와 섞이지 않는다: 사용자의 `.git` · `.oxy` 는 넣지 않는다. 사용자의 git 기록 · 브랜치는 건드리지 않는다.
- 스냅숏을 남기는 때
  - Flow 시작 (기준점)
  - Task 가 끝날 때 (`done` · `dropped`). 커밋 메시지에 Flow id · Task id · 이름을 적는다
  - 롤백 직전 (지금 상태를 보존해 되돌리기를 되돌릴 수 있게)
- Task 사이의 변경은 다음 스냅숏의 Task 에 붙는다. 계획 밖에서 한 변경은 `(계획 밖)` 으로 남는다.
- 사용자 저장소가 git 이면 사용자 커밋 노드는 지금처럼 기록하고 화면에도 보인다. 되돌리기는 늘 그림자 저장소로 한다 (git 이든 아니든 같은 방법).

## 5. 롤백 · 되돌리기

롤백 (Flow F 의 Task T 까지)
1. 지금 작업 폴더의 스냅숏을 남긴다.
2. F 안에서 T 뒤의 Task 스냅숏들의 변경을 거꾸로 되돌리는 것을 `git merge-tree` 로 미리 본다. 충돌이면 `X`, 멈춘다.
3. 충돌이 없으면 되돌린 결과를 하나의 "롤백 커밋" 으로 그림자 저장소에 남기고, 바뀐 파일만 작업 폴더에 쓴다.
4. `!` 인 경우: 3 을 한 뒤, 스냅숏에 없는 변경은 에이전트에게 Task 이름 · 요약 · 변경 파일과 함께 넘겨 되돌리기를 시도하게 한다 (시작 전 사용자 확인).
5. F 에 `↶` 줄을 붙인다. 사용자 저장소가 git 이면 바뀐 파일은 커밋하지 않은 변경으로 남는다 (커밋은 사용자 · 에이전트가 평소처럼).

되돌리기 (D3): 롤백 커밋을 다시 revert 한다. 같은 방법으로 충돌을 미리 보고, 충돌이면 `X` 로 막는다.

기호 계산: 화면에 Completed Flow 를 펼칠 때와 새 스냅숏이 생길 때 계산하고, 그림자 저장소의 HEAD 가 같으면 다시 쓰지 않는다.

## 8. 구현 기록 (2026-11-14, 부모)

- 1단계 그림자 저장소: `agent/extensions/oxy-flow/shadow.ts`. 부모 없는 스냅숏 커밋 + `refs/oxy/<flow>/<순번>`, 제외는 `info/exclude` + 작업 폴더 `.gitignore` + 20MB 상한(넘으면 exclude 에 더하고 그 Task 를 `!`). git 아닌 폴더는 `workFolderOf` 가 위로 올라가며 프로젝트 표시 파일(`pom.xml` · `package.json` 등)이 있는 폴더를 작업 폴더로 본다. 홈 폴더 · 드라이브 루트는 따라가지 않는다.
- 스냅숏 때: edit · write · bash 가 실행되기 전(`tool_call`)에 그 작업 폴더를 처음 보면 기준 스냅숏, Task 가 done · dropped 가 될 때, Flow 를 보관할 때(끝), 되돌리기 직전. 스냅숏 밖 변경(작업 폴더 밖 파일, 패키지 설치 · 외부 DB 명령, 큰 파일)은 다음 Task 의 `incomplete` 로 남는다.
- 2단계 되돌리기: `rollback.ts` (`planRollback` · `applyRollback` · `undoRollback` · `taskMarks`), 엔진 `rollbackTo` · `undoLast` · `writeMarks`(→ `.oxy/flow/marks.json`: Task 별 기호와 바뀔 파일 수). 미리 보기는 `git merge-tree --write-tree --merge-base`, 쓰기는 `read-tree -m -u` (바뀐 파일만).
